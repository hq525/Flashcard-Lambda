# Security remediation design

The user requested fixes for every issue in the 2026-09-20 audit and confirmed that this deployed application is for one owner with one private library. Preserve existing card IDs, content, review history, and recoverable images. Prepare a safe deployment/migration procedure; do not deploy or mutate production data during implementation.

Authentication: an admin-created Cognito user pool account, authorization-code login with PKCE, no public signup or browser secret. Both API Gateway and the Go application verify identity. The Go layer verifies issuer, audience, expiry, RS256 signature, ID-token use, and membership of the `owner` group. Missing configuration fails closed. The SPA uses `oidc-client-ts`, a session-scoped token store, and clears private query data on explicit logout or invalid/different owner identity. As authorized in the usability follow-up, transient refresh failures get bounded retries, and expiry locks API/UI access while retaining drafts and query state only in tab memory for same-owner popup reauthentication.

Images: remove presigned uploads and client-supplied image URLs from mutations. POST raw image bytes to `/card-question-image?cardId=...&sequenceNumber=...` or `/card-answer-section-image?cardAnswerSectionId=...&sequenceNumber=...`; return the created image DTO. Enforce 4 MiB input, decoded-dimension/pixel limits, supported JPEG/PNG/GIF/WebP, and decode/re-encode into a safe static PNG/JPEG. The input limit leaves room for base64 within Lambda's synchronous payload limit. Existing larger images can be migrated through a separate bounded administrative command. The server generates record IDs and immutable `storage_key` values of `images/<UUID>.png` or `.jpg`, verifies typed parents, and limits daily uploads. Updates accept only sequence numbers. Get/list responses expose short-lived signed read URLs; the SPA refreshes them and accepts only the configured media origin. Storage deletes use the validated immutable key bound to the image ID and the one configured bucket. Runtime code never interprets a client or legacy URL as a delete target.

Deployment: SAM keeps existing table/bucket logical IDs and names, enables private S3, versioning and retention, DynamoDB PITR, restricted IAM, origin-specific CORS, and Cognito resources. Stage throttles replace the public API key usage plan. API access/error responses include safe headers. Images lacking a migrated key do not emit legacy public URLs. A dry-run-first migration validates source buckets/keys, normalizes and copies images to server-managed keys, and conditionally updates unchanged records. Original media is preserved for recovery. A maintenance cutover freezes and drains old writes and outstanding upload grants, backs up data, deploys the authenticated backend and private bucket, provisions owner access, migrates any legacy media, releases the matching frontend, and verifies access controls and old-key retirement. The coordinated maintenance window handles these breaking changes without a legacy authentication bypass.

Other audit fixes: loopback-only development defaults, bounded HTTP bodies/fields/responses/query work with explicit errors instead of silent truncation, typed reads and parent validation, finite HTTP timeouts, private media and browser security headers, ignored environment files, patched dependencies, and a Go 1.26.8 minimum/toolchain. Old audit probes remain historical evidence, not the security regression suite.

Testing: regression tests must reject unauthenticated/non-owner/wrong-issuer/wrong-audience/expired tokens; forged image URLs/keys, missing parents, oversized and disguised uploads, external media origins; and verify safe CRUD/review behavior, content preservation, migration idempotency/conflicts, session clearing, and complete frontend/backend suites. Validate SAM and fresh dependency scans. No production credential values go into source or test output.
